# 3. 정합과 합치기

FR3 데이터만 고쳐 FR5 규약에 맞췄다. FR5 데이터와 FR5 실행 계층은 그대로 둔다. 그래야 B0와 비교된다.

## 3.1 축 방향

두 좌표계 모두 x가 로봇에서 멀어지는 방향, z가 위다. 원칙상 y도 같아야 하지만 FR3 쪽에 Y 반전 이력
(`task6_rollout_velocity_streaming.py.bak_before_yflip`)이 있어 확인했다.

FR3 시작 프레임 시트([04_coverage.md](04_coverage.md))를 보고 접시가 그릇의 어느 쪽에 있는지로 판을 나눈 뒤,
데이터상 이동 방향(배치 지점 − 파지 지점)의 부호를 봤다(`tools/03_align_merge/axis_check.py`).

| 그룹 (화면 기준) | 판 | dx 평균 | dy 평균 | 부호 |
|---|---|---|---|---|
| 접시가 그릇 오른쪽 | 0, 7, 11, 25, 64, 65, 73 | −0.012 | +0.238 | dy 7/7 양수 |
| 접시가 그릇 왼쪽 | 10, 35, 66, 76, 78, 85 | +0.010 | −0.184 | dy 6/6 음수 |
| 접시가 그릇 앞쪽 | 1, 2, 3, 4 | +0.062 | −0.001 | dx 3/4 양수 |
| FR5 전체 (접시가 늘 왼쪽 앞) | 201판 | +0.104 | −0.188 | dy 100 % 음수 |

같은 규약이다. y는 반전하지 않는다. 3번 판 하나는 시트를 보고 나눌 때 잘못 분류한 것으로 본다.

## 3.2 z 오프셋

처음 닫는 순간의 TCP z 중앙값이 FR3 0.0767 m, FR5 0.0575 m다. 차이 **−19.2 mm**를 FR3 z에 더했다.

작업대 높이와 공구 길이가 달라서 생기는 차이다. 맞추지 않으면 정책이 FR5에서 더 높은 곳에서 그리퍼를 닫는 쪽으로
배울 수 있다. 처음에 인계 문서의 FR3 파지 높이(0.0875 m)로 계산한 28.5 mm는 기준이 다른 값이었다.

## 3.3 회전

두 데이터 모두 손끝이 아래를 보는 거의 180° 회전이지만 접근축 둘레 방위가 다르다. 시작 자세 툴 x축이 FR3 +2.2°,
FR5 −78.3°다.

FR5 쪽 문서는 이 차이를 "물리적으로 자연스러운 방향을 그대로 쓴 것"으로 설명한다. FR5 base가 장면에 대해 약 77° 돌아
있고, 작업자는 손목을 base 기준 자연스러운 방향으로 둔 채 수집했다. 회전은 실행에 쓰지 않지만 state 입력에는
들어가므로 FR3 쪽을 FR5에 맞췄다.

```
R_off = mean(R_FR3_start)^-1 · mean(R_FR5_start)      툴 좌표계, 80.4°
R_FR3_aligned = R_FR3 · R_off                          프레임 사이 실제 회전량은 원본과 같다
```

축각은 판마다 첫 프레임을 FR5 기준값 `ref_axis_angle = [-2.44253, 1.96807, 0.00198]`에 가까운 표현으로 고르고,
이후 프레임은 직전 프레임에 가까운 표현으로 골라 판 안에서 이어지게 했다.

## 3.4 정합 실행과 검증

`tools/03_align_merge/align_fr3.py` → `data/fr3_task6_aligned_v1`

```
회전 오프셋 (tool frame)            80.4 deg  euler xyz [-0.56  1.26 80.4]
action[t]==state[t+1] 최대 오차     0.00e+00
판 안 축각 최대 점프                0.347 rad
시작 자세 차 (정합 후, FR5 대비)     0.00 deg
```

최대 점프 0.347 rad는 표현이 갈린 것이 아니다. 갈렸다면 약 6.3 rad(2π)로 나온다. 회전 크기가 π 근처면 작은 실제
회전도 축각 벡터에서는 크게 보이고, FR3는 프레임 간격도 약 0.36초로 길다.

`meta/stats.json`과 에피소드별 통계도 다시 계산했다. `norm_stats.json`은 값이 맞지 않게 되므로 `.stale`로 이름만
바꿨다. GR00T 학습은 이 파일을 쓰지 않는다(쓰는 코드는 molmoact2뿐).

## 3.5 맞추지 않은 것

| 항목 | 이유 |
|---|---|
| xy 위치 | 두 장면을 잇는 기준점이 없다. FR3 쪽 인덕션 좌표를 잴 수 없다. `use_relative_actions=true`라 action에는 영향이 작고 state 입력에 남는다 |
| 기록 주기 (2.8 / 3.4 Hz) | 1차에서는 그대로. 재샘플링은 절제 실험으로 남김 |
| 그리퍼 기구 | Franka Hand와 AG-95. 폭 범위는 이미 같다 |

## 3.6 합치기

LeRobot `aggregate_datasets`(학습 서버의 `lerobot/datasets/aggregate.py`)를 썼다. 이 함수는 fps, robot_type, features가
모두 같아야 합친다. features와 fps는 같았고 robot_type만 달라서, 정합 사본의 `robot_type`만 `fairino_fr5`로 바꿨다
(`set_robot_type.sh`, `ALIGNMENT_NOTE.txt`에 기록). 원본 FR3 데이터는 건드리지 않았다.

FR5를 앞에 두고 합쳤다. 0~204번이 FR5, 205~404번이 FR3 에피소드다.

```
episodes 405   frames 21863   robot_type fairino_fr5   fps 10   task 1
ep 0    state [0.4413, -0.0146, 0.2902, -2.4425, 1.9681, 0.0020, 0.04, -0.04]     ← FR5 0번 판 첫 프레임
ep 404  state [0.7280,  0.1992, 0.0839, -2.6288, 1.6967, 0.0062, 0.0399, -0.0399] ← FR3 정합본
stats state min [0.3409, -0.1523, 0.0303, -3.2169, 0.7884, -0.5075, 0.0014, -0.0405]
stats state max [0.8158,  0.4282, 0.4710, -1.9609, 2.6840,  0.9952, 0.0405, -0.0014]
```

합친 데이터의 범위가 FR5 단독보다 넓어졌다. y 최솟값 −0.152(FR5 −0.067), z 최솟값 0.030(FR5 0.046)이다. 이것이
작업 상자를 넣은 이유다([06_safety_and_ops.md](06_safety_and_ops.md)).
