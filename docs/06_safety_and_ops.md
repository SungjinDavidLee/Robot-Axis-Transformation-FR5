# 6. 안전과 운영

## 6.1 원래 있던 안전층

FR5-GR00T-Benchmark의 실행 계층을 그대로 쓴다.

```
경로 추종      관절 6 °/s, 청크 32개를 한 경로로
제어판 필터    속도 15, 가속 120 °/s², 관절 소프트 한계, 바닥 45 mm, 값 튐 차단
롤아웃 검사    목표마다 IK 오차 > 2 mm 또는 관절 변화 > 20° 이면 그 목표를 건너뜀
회전           정책 출력을 쓰지 않고 시작 자세 유지
종료           MAXSTEPS, 놓침 판정, 사람이 [e]
--dry          로봇에 아무 명령도 보내지 않음
```

## 6.2 FR3 데이터가 더한 위험

| 위험 | 근거 | 처리 |
|---|---|---|
| 좌우로 더 나간 목표 | 합친 데이터 y 최솟값 −0.152, FR5만은 −0.067. 화면 왼쪽(인덕션·캐비닛 쪽) | 작업 상자 추가 |
| 바닥 아래 z | 합친 데이터 z 최솟값 0.030 < 바닥 45 mm | 제어판 바닥 필터가 막음 |
| 한 스텝의 이동이 큼 | FR3 기록 주기 2.8 Hz | 관절 점프 차단이 더 자주 걸릴 수 있음 — 안전 쪽 |

## 6.3 작업 상자

`tools/05_robot/patch_box.py`로 `fr5_rollout.py`에 넣었다. 정책 목표가 FR5 시연 범위에 1 cm 여유를 더한 상자를 벗어나면
그 청크를 거기서 끊는다.

```
BOX_XY   = 0.37, 0.82, −0.08, 0.44   (작업 프레임 x0, x1, y0, y1, m)
BOX_ZMAX = 0.39
```

기준 줄이 파일에 정확히 한 번 있을 때만 고치고, 고치기 전에 백업을 남긴다
(`fr5_rollout.py.bak_20261003_190202`). B0와 C1 모두 같은 파일로 돌므로 하네스 조건이 같다. 본 측정 30판 동안
상자는 한 번도 발동하지 않았다.

인덕션·캐비닛 출입 금지 구역은 좌표가 없어 넣지 않았다. 측정 도구(`probe_points.py`)는 만들어 뒀지만 쓰지 않았다.
시운전에서 인덕션 쪽으로 가는 동작이 보이면 그때 재기로 했고, 보이지 않았다.

## 6.4 시운전

```
1. C1-12k 를 절반 속도(VPATH=3)로, 비상정지에 손을 올리고 1판
2. 이상 없으면 정상 속도
3. 그리퍼 힘 100 % → 미끄러짐 → 70 % 로 변경 (--force 70)
4. 인덕션 왼쪽 그릇(B0 가 못 집던 자리)에서 픽 시도 — 집음, 놓기 실패
```

## 6.5 손목 고정 회전 옵션

`patch_yaw.py`로 `YAW_OFF`(도) 환경 변수를 넣었다. 시작 자세에 접근축 둘레 고정 회전을 더한다. 기본값 0이면 동작이
바뀌지 않는다. 미끄러짐 원인 시험에만 썼다([08_slip.md](08_slip.md)).

## 6.6 운영하면서 생긴 일

같은 일을 반복하지 않으려고 적어 둔다.

| 일 | 원인 | 처리 |
|---|---|---|
| 배치만 하려다 B0 롤아웃이 한 판 돌았다 | `bench_runner`에서 `s`가 눌림. `SERVER` 미지정이라 B0(:8200) | 기록 태그가 `drycheck`라 본 측정과 분리. `s`는 정책 시작 키 |
| 배치 안내(`p`)에서 로봇이 안 움직였다 | 제어판 리더 추종이 꺼져 있었다(`추종 꺼짐`) | `/leader`에서 [리더 추종 시작] 후 `p` |
| `pyrealsense2` 없음 | 시스템 python. `realsense_py310`에는 PIL이 없음 | `conda activate openvla_py310` |
| 서버 재시작 직후 첫 추론 3.6 s | 첫 요청 예열 | 이후 0.38~0.40 s. 측정 전 예열 |
| 스크립트를 다른 기계에서 실행 | 학습 서버용을 워크스테이션에서 | 프롬프트 호스트명 확인 |
| 워크스테이션 루트 100 % | 기존 사용량 | 작업 폴더를 `/home/data/fr_transfer`로 옮기고 링크 |
| `python3 -m venv` 실패 | `ensurepip` 없음 | `python3.12-venv` 설치, pip은 `get-pip.py` |
| C1 서버 `ref_axis_angle` null | `norm_stats.json` 미복사 | [05_training.md](05_training.md) 5.4 |
| 미끄러짐을 `c`로 기록 | v1 기록기에는 미끄러짐 선택지가 없고 `c`가 '접시 밖' | 로그로 재분류. 11번 세트부터 v3 사용 |
| 우연히 접시에 떨어진 판을 `s`로 기록 | 현장 판단 | `end_why`로 엄격 재분류 |

## 6.7 기록기 버전

```
bench_runner.py      2026-09-28 11:18   v1   원인 a 정체 / b 헛잡음 / c 접시 밖 / d 미해제
bench_runner_v2.py   2026-09-28 11:59
bench_runner_v3.py   2026-09-28 15:07   9/28 본 측정(main_S01~, 16:20 시작)에 쓴 버전
bench_runner_v4.py   2026-09-29 14:13
```

9/28 기록 행에는 힘(70)과 밀림 칸이 있고, v1은 이 칸을 남기지 않는다. 그래서 9/28 측정은 v3로 본다. v1과 v3의 차이는
원인 코드(v3: a 정체 / b 헛잡음 / c 이송 중 놓침 / d 접시 밖 / e 미해제), 힘·밀림 기록 칸, `--force-cycle`(세트마다
돌려 쓸 힘 목록, 값 하나면 `--force`와 같다)뿐이다. 힘을 보내는 시점과 방법은 같고, 두 버전 모두 레지스터를 다시
읽지는 않는다. 로봇 동작이 같으므로 C1 세트 1~10(v1)은 살리고 11~30을 v3로 돌렸다.
