# 1. 출발점

## 1.1 처음 세운 그림

같은 태스크를 두 로봇에서 모았다.

```
Franka FR3   7축   Franka Hand   GELLO 7축 리더   200판
FAIRINO FR5  6축   DH AG-95      U-Arm 6축 리더   205판
```

FR3 데이터는 FR5보다 넓은 작업대에서 모았다. 처음 목표는 "7축 데이터를 6축 로봇으로 옮기는 것"을 연구 주제로
세우는 것이었고, 참고 논문으로 RoVi-Aug(로봇·시점 증강)와 SPACE(arXiv 2606.24049, Cartesian state delta를
공통 action으로 쓰는 프레임워크)를 잡았다.

## 1.2 진행하면서 바로잡은 전제

**7축 → 6축은 관절 수 문제가 아니다.** 6축 팔은 작업공간 안에서 특이점과 관절 한계만 피하면 임의의 6D 손끝 자세를
낼 수 있다. 7번째 축이 담던 정보는 팔꿈치 자세(영공간)뿐이고, 이 태스크에는 필요 없다. 실제로 갈리는 것은 관절
한계, 특이점, IK 가지, 작업대·카메라·그리퍼·제어 동역학이다.

**이 태스크에서는 회전도 쓰지 않는다.** FR5 롤아웃은 정책의 회전 출력을 버리고 시작 자세를 유지하고, FR3 쪽
컨트롤러도 회전 명령을 버린다. 실제로 옮겨지는 action은 위치 3 + 그리퍼 1이다. 두 로봇 모두 이 공간을 그대로 낼 수
있으므로, 관절 수 차이는 실험에서 거의 드러나지 않는다.

**방향만으로는 새롭지 않다.** SPACE가 이미 UR5(6축) 데이터를 FR3(7축)에 섞는 co-training을 했다. 7 → 6이라는
방향 자체를 기여로 잡기는 어렵다.

**"성공하면 정책이 인지 과정을 이해했다는 증거"는 과한 주장이다.** 손끝 좌표 공간을 공유하는 것만으로 설명되는
결과이므로 그렇게 쓰지 않는다.

## 1.3 첫 번째 설계 — FR5의 빈 영역 채우기

FR5 정책은 그릇이 인덕션 오른쪽 끝보다 왼쪽에 놓이면 집지 못했다. FR5 시연에서 그 자리를 집은 적이 없기
때문이다. FR3 작업대가 더 넓으니 FR3 데이터가 그 영역을 덮고 있다면, "FR3 데이터로 FR5의 공간 커버리지를 넓힌다"는
측정 가능한 주장이 선다고 봤다.

FR3 실물은 만질 수 없어서 영상으로 판정했다. 결과는 **no-go**였다. FR3 200판 중 그릇이 그 영역에 확실히 놓인 판은
3판(7, 8, 11번)뿐이었다. 과정은 [04_coverage.md](04_coverage.md).

## 1.4 최종 목표 — FR5 성공률 올리기

목표를 단순하게 다시 잡았다.

> FR3 데이터를 섞어 학습한 정책이 기존 FR5 단독 정책보다 성공률이 높으면 성공이다.

약점 하나를 메우는 실험이 아니라, 같은 평가에서 성능이 오르는지를 본다. 이렇게 정하면서 지킬 조건도 함께 정했다.

```
바꾸는 것    학습 데이터 하나 (FR5 205판 → FR5 205판 + FR3 200판)
같게 둘 것   30세트 배치, 배치 방식, 실행 하네스 규칙, 그리퍼 힘, 판정 기준
주 지표      파지 성공률 (S5)과 헛잡음 수  — 평가 전에 정함
보조 지표    최종 성공률 (S9)
비교 기준    9/28 B0 30판 (FR5-GR00T-Benchmark)
```

주 지표를 결과를 보기 전에 정한 이유는, 결과를 본 뒤 유리한 지표를 고르는 일을 막기 위해서다. 주 비교 체크포인트도
같은 이유로 평가 전에 12,000스텝으로 정했다([05_training.md](05_training.md)).

## 1.5 설계 결정 요약

| 결정 | 이유 |
|---|---|
| 섞기(co-training) | FR3만으로 학습해 FR5에서 돌리는 것보다 가설에 직접 맞는다 |
| action 형식 그대로 | 두 데이터가 이미 같은 형식(EE 절대 pose, `action[t] = state[t+1][:7]`)이다 |
| 좌표 보정은 FR3 쪽만 | FR5 데이터와 FR5 실행 계층을 그대로 둬야 B0와 비교된다 |
| embodiment 하나 | LeRobot의 `groot` 정책이 embodiment 태그를 하나만 받는다. 그래서 정합이 필수였다 |
| xy 정렬은 하지 않음 | FR3 쪽 장면 기준점(인덕션 좌표)을 잴 수 없었다 |
